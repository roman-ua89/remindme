# Known issues

**Screen support:** for now only screens 768px wide and above are supported; the mobile version is out of scope. Agents must not run checks (browser, screenshot or layout) at mobile resolutions: use viewports of 768px and wider, and don't report problems that appear only below 768px.

- Constructor form resets only when `entity.id`/`editedAt` changes (`EntityConstructorPage`). Any new endpoint that changes title/blocks must also bump `editedAt`, and toggle-style endpoints must not, or the form will either miss server changes or wipe unsaved edits.
- Play buttons on Topic/Category/Entity cards stay enabled even when every entity in scope is hidden; the DTOs carry no included-entity count, so the Player will just come back empty.
- `npx shadcn add` adds a stray `cn` dependency to package.json and generates `import { cn } from "cn"`; revert package.json/lock and use `@/lib/utils`.
- `.mcp.json` is tracked and contains a literal context7 API key. Rotate it and switch to `${CONTEXT7_API_KEY}` before the repo is pushed anywhere (Phase 0 of `docs/agentic-cicd-plan.md`).
- Mermaid 11 (GitHub's renderer) rejects a `gitGraph` that merges into a branch with no commits of its own ("Cannot merge branch into itself"); give the target branch a commit first.
- On a fresh checkout, the backend `typecheck` (and `tsc` in `build`) fails with "`@prisma/client` has no exported member `Prisma`" until `npm run db:generate -w backend` has run. CI generates the Prisma client before `npm run ci` (step 2.1 in `.github/workflows/ci.yml`).
- `backend/tsconfig.json` has no test exclusion, so `npm run build -w backend` also emits `dist/lib/*.test.js`, which imports vitest. `start` never loads them, but test code ships in `dist`.
- `frontend/src/features/entities/schemas.ts` re-declares the entity and block schemas instead of extending the contracts in `packages/contracts`, which CLAUDE.md asks for. The `to-save-payload` tests exercise this copy, not the contract.
- `.claude/hooks/format-file.sh` needs `jq` on `PATH`. Without it the hook exits 2 with a message on every Edit/Write, so install `jq` on a new machine before editing.
- The format hook covers `frontend/src` `.ts`/`.tsx` only. `.css` files in `frontend/src` (for example `styles.css`, `index.css`) are not formatted on edit; `npm run format:check` in `frontend/` still catches them.
- `npm run ci` (its `vite build` step) rewrites `frontend/src/routeTree.gen.ts` in the TanStack generator's own style, so the file shows as modified afterwards. Run `git checkout -- frontend/src/routeTree.gen.ts` before committing, and don't stage it.
- After `npm run build`, `backend/dist` holds compiled `*.test.js` files. The backend vitest run has no config, so it picks them up and every backend test runs twice (24 instead of 12). Add a backend `vitest.config` that excludes `dist`.
- The lock file was generated on macOS, so it has only `@tailwindcss/oxide-darwin-arm64`. On the Linux runner `npm ci` then fails while loading `frontend/vite.config.ts` ("Cannot find module './tailwindcss-oxide.linux-x64-gnu.node'"). `npm install` will not add a missing optional platform package to an existing lock, so `frontend/package.json` declares `@tailwindcss/oxide-linux-x64-gnu` as an exact optional dependency. Keep that pin in step with `@tailwindcss/oxide` when Tailwind is upgraded.
- `vercel build` and `vercel dev` create `frontend/.vercel` and `backend/.vercel`. Prettier `format:check` then fails in `npm run ci`, so delete those two folders after each Vercel run (`.vercel/` in `.gitignore` does not stop Prettier). `vercel build` also writes the repo-root `.vercel/output`; delete that too, but keep `.vercel/project.json`, which links the project. `vercel dev` and `vercel build` also rewrite `frontend/src/routeTree.gen.ts`; restore it with `git checkout --` before committing. `vercel dev` can leave its Vite child running after it stops (it is re-parented to launchd and keeps rewriting that file), so check `pgrep -fl vite` and stop any left over.
- Vercel's build runs `npm` with install scripts blocked (`@prisma/client` postinstall among them), so `postinstall` does not generate the Prisma client during `vercel build`. Step 3.5 generates it with `npm run db:generate` in a `buildCommand` under `services.backend` in `vercel.json`; a top-level `buildCommand` is rejected while `services` is set.
- `vercel build` lists the Prisma engine (`libquery_engine-rhel-openssl-3.0.x.so.node`) in the backend function's `.vc-config.json` `filePathMap`, but does not copy it into `.vercel/output`; only the experimental `vercel build --standalone` does. Whether the engine loads on Vercel's runtime is unverified until the Phase 4 deploy.
- The schema's `directUrl = env("DIRECT_URL")` means `prisma migrate dev` and `prisma validate` fail on a local `backend/.env` without a `DIRECT_URL` line (copy `DATABASE_URL`).
- The Vite `/api` proxy target is hardcoded to `http://localhost:3000` (`frontend/vite.config.ts`), but the backend reads `PORT`. If `PORT` changes, change the proxy target too. A `VITE_API_URL` line in a local `frontend/.env` overrides the relative default, so dev skips the proxy until that line is removed.
- The `vercel-blob` storage driver has no tests and has not run against Vercel Blob. Its first real check is the Phase 4 deploy.
- A failed `del` in `deleteMediaAssetsIfUnreferenced` is swallowed, so the blob stays behind with no database row. Nothing cleans these up yet.
- Setting `CORS_ORIGIN` to an empty string (for example `CORS_ORIGIN=` in Vercel) fails the URL check in `env.ts` and exits at startup. Leave the variable unset to turn CORS off, as the cloud deployment does.
- `seed-dev` refuses to run when `NODE_ENV=production`, but it reads `NODE_ENV` from the shell only: the seed does not load `backend/.env`, so `NODE_ENV=production` written in that file does not stop it.
- `prisma.seed` (run by `prisma migrate reset`) chains `npm run db:seed:base && npm run db:seed:dev`. This is not tested, because `migrate reset` drops the database.
- While an earlier task branch is unmerged, "previous commit + 1" on `dev` gives that branch's number again. `create-branch` stops and asks, but `commit-message` would compute the taken number too. This is open: the skill's Number rule does not handle it. Until it does, compare the draft's number with the branch name, which holds the number the user chose, before offering the commit.
- `node_modules` does not follow a branch switch: when `package.json` differs, `vite build` can fail with "Can't resolve …". Run `npm ci` from the root after such a switch; `npm install` can rewrite the range entries in `package-lock.json`.
- `builder` may decline an edit to `CLAUDE.md` even when the brief says the user approved it (seen 2026-11-22: it would not act on a relayed approval), so such a brief can come back with that file unchanged.
- **Cyrillic, still to decide:** Figtree and Fraunces have no Cyrillic glyphs (Inter had them), and 55 of the 295 entity titles in the dev database use Cyrillic (counted 2026-11-22). Such text falls back to the system sans, and to the system serif in headings (Georgia on macOS), so mixed-script lines use two typefaces and look different per OS. If that is not acceptable, change `--font-heading` (and `--font-sans`) in `index.css`: the logo and header from Step 3 use the tokens, so they follow.
- **Contrast, fix before Redesign Steps 8 and 9:** still under WCAG AA 4.5:1 for normal-size text: `block-list` on its soft background 3.62, link URL `#4F7DA8` on `block-link-surface` 4.07, `primary` text on `background` 4.48 (the `link` button and the Step 5 eyebrow use `primary-hover` for this reason). The disabled `positive` button is white on `#C3DBB6`, 1.49:1: WCAG exempts disabled controls, but it is hard to read, so decide on its text colour before Step 8 puts it on Save, which starts disabled.
- **Interim look after Redesign Step 2:** Done, Save, Skip and Stop keep their old variants (terracotta or outline) until Steps 8 and 9 apply `positive`, `secondary` and `stop`. The marker toggle in the Constructor waits for Step 8 (the list search and pagination were restyled in Step 7). Headings keep their bold or semibold classes, not Fraunces 500, until each page's step restyles them.
- **Constructor overflow at 768px, fix in Redesign Step 8:** the page scrolls 230px sideways and the templates panel is cut off, because the content column does not shrink below its content (the text editor toolbar is one long row). Measured at 230px both on `dev` at 480ec0b and on a build with the Step 2 changes.
- **Text over the sun (since Redesign Step 3):** the rings lower contrast in the top-left 300px. `muted-foreground` drops from 5.40 to 4.75 inside the 130px ring and 4.06 inside the 70px one; `primary` text, already 4.48 on paper, drops to 3.37–4.38. Today's muted text there stays at 4.74 or above at 768px and 1280px. Keep muted text out of the 70px core, and use `primary-hover` for small accent text over the sun.
- **Constructor hint contrast, fix in Redesign Step 8:** "(max 75 symbols)" next to Title is 2.36:1 on paper and 2.22:1 over the sun at 768px, under WCAG AA 4.5:1.
- An opaque background on a page wrapper hides `SunGlow`, which sits at `-z-10` in `__root`. Put backgrounds on cards and panels, not on the page root.
- Dev servers started with the desktop app's `preview_start` can hang silently with no open port: on 2026-11-22 `npm` blocked in `getcwd` under `~/Documents`, probably on a macOS folder-access prompt for that launcher. The same scripts run normally from the agent's shell.
- `push-commit` cannot push follow-up commits: step 1 stops when origin has the branch at a different commit, and an older commit of the same branch counts as different. This is open until the human decides whether it may make a plain fast-forward push there; until then it stops and reports, and stays on the branch.
- Markdown can fail `npm run ci`. Prettier checks `frontend/README.md` and `backend/README.md`, and Tailwind takes class names from every `.md` under `frontend/`, docs included: for example, `[@import_x]:flex` in `frontend/docs/PRODUCT.md` breaks `vite build`. If a script, test or config starts reading `.md` in a path the skip-ci check treats as safe, take that path out of the check.
- **Placeholder score (since Redesign Step 4):** `frontend/src/features/score/placeholder.ts` is temporary and random: no API or persistence, not tied to the user or to real activity, a new value on every page reload and the same value after a logout without reload. Replace it when score logic is implemented (`TODO(score)`).
- **Tree stage ranges, still to decide:** `getTreeStage` applies day ranges to drops, so at up to 3 drops a day the last stage (12 drops) takes as few as 4 days, not 12. The guest Home labels follow these ranges (decided in Redesign Step 5). Settle the unit with score logic.
