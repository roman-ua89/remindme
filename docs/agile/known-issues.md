# Known issues

- Constructor form resets only when `entity.id`/`editedAt` changes (`EntityConstructorPage`). Any new endpoint that changes title/blocks must also bump `editedAt`, and toggle-style endpoints must not, or the form will either miss server changes or wipe unsaved edits.
- Play buttons on Topic/Category/Entity cards stay enabled even when every entity in scope is hidden; the DTOs carry no included-entity count, so the Player will just come back empty.
- `npx shadcn add` adds a stray `cn` dependency to package.json and generates `import { cn } from "cn"`; revert package.json/lock and use `@/lib/utils`.
- `.mcp.json` is tracked and contains a literal context7 API key. Rotate it and switch to `${CONTEXT7_API_KEY}` before the repo is pushed anywhere (Phase 0 of `docs/agentic-cicd-plan.md`).
- Mermaid 11 (GitHub's renderer) rejects a `gitGraph` that merges into a branch with no commits of its own ("Cannot merge branch into itself"); give the target branch a commit first.
- On a fresh checkout, the backend `typecheck` (and `tsc` in `build`) fails with "`@prisma/client` has no exported member `Prisma`" until `npm run db:generate -w backend` has run. CI generates the Prisma client before `npm run ci` (step 2.1 in `.github/workflows/ci.yml`).
- `backend/tsconfig.json` has no test exclusion, so `npm run build -w backend` also emits `dist/lib/*.test.js`, which imports vitest. `start` never loads them, but test code ships in `dist`.
- `frontend/src/features/entities/schemas.ts` re-declares the entity and block schemas instead of extending the contracts in `packages/contracts`, which CLAUDE.md asks for. The `to-save-payload` tests exercise this copy, not the contract.
- `.claude/hooks/format-file.sh` needs `jq` on `PATH`. Without it the hook exits 2 with a message on every Edit/Write, so install `jq` on a new machine before editing.
- The format hook covers `frontend/src` `.ts`/`.tsx` only. `.css` files in `frontend/src` (for example `styles.css`, `index.css`) are not formatted on edit; `npm run format:check` in `frontend/` still catches them.
- `npm run ci` (its `vite build` step) rewrites `frontend/src/routeTree.gen.ts` in the TanStack generator's own style, so the file shows as modified afterwards. Run `git checkout -- frontend/src/routeTree.gen.ts` before committing, and don't stage it.
- After `npm run build`, `backend/dist` holds compiled `*.test.js` files. The backend vitest run has no config, so it picks them up and every backend test runs twice (24 instead of 12). Add a backend `vitest.config` that excludes `dist`.
- The lock file was generated on macOS, so it has only `@tailwindcss/oxide-darwin-arm64`. On the Linux runner `npm ci` then fails while loading `frontend/vite.config.ts` ("Cannot find module './tailwindcss-oxide.linux-x64-gnu.node'"). `npm install` will not add a missing optional platform package to an existing lock, so `frontend/package.json` declares `@tailwindcss/oxide-linux-x64-gnu` as an exact optional dependency. Keep that pin in step with `@tailwindcss/oxide` when Tailwind is upgraded.
- `vercel build` and `vercel dev` create `frontend/.vercel` and `backend/.vercel`. Prettier `format:check` then fails in `npm run ci`, so delete those two folders after each Vercel run (`.vercel/` in `.gitignore` does not stop Prettier). `vercel dev` and `vercel build` also rewrite `frontend/src/routeTree.gen.ts`; restore it with `git checkout --` before committing. `vercel dev` can leave its Vite child running after it stops (it is re-parented to launchd and keeps rewriting that file), so check `pgrep -fl vite` and stop any left over.
- Vercel's build runs `npm` with install scripts blocked (`@prisma/client` postinstall among them), so the Prisma client is not generated during `vercel build`. Step 3.5 has to add the generation.
