# Decisions

- 2026-11-12 Topic visibility has no DB column: it is derived from its entities (`excluded` iff the topic has ≥1 entity and all are excluded). Toggling a topic cascades `updateMany` to all its entities; turning it back on resets every entity to visible.
- 2026-11-12 Entity visibility switches stay enabled when the parent topic is off (backlog Task 1 line 18 wins over line 10); turning one entity on makes the topic visible again.
- 2026-11-12 Visibility has dedicated endpoints (`PATCH …/entities/:id/visibility`, `PATCH …/topics/:id/visibility`) like `/marker`, so toggling does not bump `editedAt`.
- 2026-11-12 Commit messages are drafted to `.git/commit-message-draft.txt` and committed with `git commit -F` only after the user approves, so the text can be edited before the commit exists. Files are staged by name, never `git add -A`.
- 2026-11-14 No staging environment. A push to `dev` that passes CI deploys straight to production: it's deployed with `--skip-domain`, smoke-tested, then promoted. `prod` is never committed to; the pipeline fast-forwards it to the deployed SHA, so it always shows what's live. The `PROD_AUTO_DEPLOY=false` repo variable pauses automatic deploys.
- 2026-11-14 Every change reaches `dev` through a PR from a short-lived feature branch (`feat/…`, `fix/…`, `chore/…`, `claude/…` for agents), squash-merged. The `dev` ruleset requires the PR and green `ci / quality` + `ci / migrations` with 0 approvals and no bypass, so direct pushes are rejected for the owner too. The merge is the deploy decision and stays human; agents never merge.
- 2026-11-16 The public GitHub history is kept as it is. The old context7 key (rotated; revocation to be confirmed in the dashboard) stays in commits `92173c1` and `dd1485b`, and every commit carries the work email. No history rewrite and no force-push to `dev` or `prod`, so the no-force-push rule holds.
- 2026-11-16 Feature branches are named `<type>/<number>_<short_task_name>`, e.g. `feature/33_some_task_name`. `type` is `feature` (or `fix`, `chore`), the number matches the commit number, and the name uses underscores, has 1–4 words and says what the task is about. `feat` is replaced by `feature`. Agent branches keep the `claude/` prefix until decided otherwise.
- 2026-11-16 The `create-branch` skill, run by the orchestrator at task start, is the only place that creates a task branch. `commit-message` commits on the checked-out branch and never creates one.
- 2026-11-16 Each task runs on the branch `create-branch` makes, chat or backlog. When the human picks it in the `merge-branch` dialog, the branch is fast-forwarded into `dev` and deleted locally. Until then it stays checked out, so the feature can be tested first.
- 2026-11-16 Supersedes the merge rules of 2026-11-14 for local task branches: `merge-branch` fast-forwards the task branch into local `dev`, pushes `dev` to origin right away with a plain push, and then deletes the branch, only after the human picks "Merge and push". It never force-pushes. Once the planned `dev` ruleset is on, this direct push will be rejected, and that change will need a PR. PRs, squash merges and "agents never merge" still apply to `claude/` branches from cloud agents.
- 2026-11-16 Until the backend gets an ESLint config (which needs devDependencies and a `package-lock.json` change), root `lint` covers the frontend only. The frontend `test` (`vitest run`) exits 1 with no test files, and the backend `test` (`node --test`) passes with zero tests; step 1.4 adds the tests. Backend `format:check` runs `prettier`, which backend does not declare; it resolves only through hoisting from frontend's devDependencies.
- 2026-11-16 Each workspace has a `format` script that writes files with Prettier (the backend's uses the same undeclared `prettier` as its `format:check`), and root `format:check` is the pipeline check. Lint fixes are not part of `format` until the `chart.tsx` crash is fixed.
- 2026-11-16 The frontend `docs/` folder (Markdown and SVG) is excluded from Prettier in both the frontend `format` and `check` scripts, so the format gate and root `format:check` skip it.
- 2026-11-16 A lint fix removes a check only when the type system proves it cannot fail (for example `blurredByDefault` is a non-optional boolean, `isLoading` implies `data` is undefined, `getCurrentUser` never returns null). A check on a value that can be missing at runtime stays and is typed as optional instead: PlayerPage's current item comes from `queue.at(0)` (typed `T | undefined`), and chart.tsx widens the tooltip label lookup's type so its `?.` stays.
- 2026-11-16 The `chart.tsx` `eslint --fix` crash from the `format` decision above no longer reproduces: a dry run over frontend `src` (`eslint --fix-dry-run src`) exits 0 with no messages. The frontend `format` script stays prettier-only until someone decides to add a lint-fix step.
- 2026-11-16 `frontend/src/routeTree.gen.ts` is excluded from Prettier in `frontend/.prettierignore`. The TanStack route generator rewrites it in its own style on every route generation, so it cannot stay Prettier-formatted. Its header also asks for exclusion from the linter; that is not done here.
- 2026-11-16 The frontend `lint:fix` script (`eslint --fix`) stays in `frontend/package.json`. The `chart.tsx` crash no longer reproduces, and a dry run over `src` passes.
- 2026-11-16 Step 1.4: the backend test runner is vitest (`^4.1.12`, installed from the root lockfile), replacing `node --test`. Frontend and backend tests run from the root `npm run test`.
- 2026-11-16 Step 1.4: `frontend/vitest.config.ts` gives vitest only `tsconfigPaths`, without the TanStack router plugin, so `npm run test` does not rewrite `src/routeTree.gen.ts`. This supersedes the 2026-11-16 line that said the frontend `test` exits 1 with no test files.
- 2026-11-16 Step 1.5: formatting and linting on edit are enforced by a `PostToolUse` hook (matcher `Edit|Write`), not by a prompt rule. The hook covers only `frontend/src` `.ts`/`.tsx`, because the eslint config lives in `frontend/`; backend files are not touched by it. It reads the file path with `jq`, and on lint errors exits 2 so the agent fixes them.
- 2026-11-16 Step 1.6: a builder reports done only after `npm run ci` (repo root) exits 0, on top of its brief's "Done when".
- 2026-11-16 Step 2.1: the `quality` job runs `npm run db:generate -w backend` before `npm run ci`, because the typecheck needs the Prisma client on a fresh checkout. Step 3.5 (`postinstall`) can replace that step later. Action pins use major tags (`actions/checkout@v7`, `actions/setup-node@v7`).
- 2026-11-17 PR #1 CI fix: `frontend/package.json` declares `@tailwindcss/oxide-linux-x64-gnu` at exact 4.3.2 as an optional dependency, because the lock was generated on macOS and `npm install` does not add missing optional platform packages to an existing lock. Its pin follows `@tailwindcss/oxide`.
- 2026-11-17 Step 2.4: `timeout-minutes` goes on the jobs that run steps in `ci.yml`, not on the `ci` caller job in `pipeline.yml`, because actionlint rejects `timeout-minutes` on a job that calls a reusable workflow with `uses:`. Plan 2.4's "every job" means every job that runs steps.
- 2026-11-17 Step 3.1: chose B (Vercel Services). A is blocked: `vercel build` fails with MISSING_SERVICES because the project's framework setting is `services`, which vercel.json cannot override and only the dashboard can change, so A waits on a human step. B's backend entrypoint is `src/app.ts`, whose default export is an async request handler that creates the Express app with `createApp()` once per function instance. A failed start-up is not cached: the next request retries `createApp()` (checked by code only, not by forcing a failure). `createApp()` and `server.ts` are unchanged; `server.ts` still calls `app.listen()` for local development. Checks: `vercel dev` returns 401 application/json for `GET /api/v1/categories`, `vercel build` passes, and the function's handler `app.js` exports that default handler. A root-level `backend/index.ts` was tried first and dropped: the production build never reached it. Caveats: the production runtime is not verified, and `ensureUploadDir()` writes to `./uploads`, which Vercel's read-only filesystem does not allow (step 3.4). Vercel builds on Node 24.x because the backend's `engines` overrides the project's 26.x setting.
- 2026-11-17 Task branches reach `dev` only through a pull request. `push-commit` pushes the task branch to origin and nothing else: it never pushes `dev`, never merges and never opens the PR, so the PR into `dev` is opened on GitHub and the human merges it once `ci / quality` and `ci / migrations` are green. This supersedes the 2026-11-16 merge rules, which fast-forwarded and pushed `dev` directly. The `dev` ruleset from plan step 2.7 blocks direct pushes.
- 2026-11-17 Step 3.2: the API base URL defaults to the relative `/api/v1` when `VITE_API_URL` is unset, and the Vite dev server proxies `/api` to `http://localhost:3000`, so dev and production are both same-origin. `resolveMediaUrl` prepends an origin only for an absolute base. `frontend/.env.example` comments out `VITE_API_URL`.
