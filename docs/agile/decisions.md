# Decisions

- 2026-11-12 Topic visibility has no DB column: it is derived from its entities (`excluded` iff the topic has ≥1 entity and all are excluded). Toggling a topic cascades `updateMany` to all its entities; turning it back on resets every entity to visible.
- 2026-11-12 Entity visibility switches stay enabled when the parent topic is off (backlog Task 1 line 18 wins over line 10); turning one entity on makes the topic visible again.
- 2026-11-12 Visibility has dedicated endpoints (`PATCH …/entities/:id/visibility`, `PATCH …/topics/:id/visibility`) like `/marker`, so toggling does not bump `editedAt`.
- 2026-11-12 Commit messages are drafted to `.git/commit-message-draft.txt` and committed with `git commit -F` only after the user approves, so the text can be edited before the commit exists. Files are staged by name, never `git add -A`.
- 2026-11-14 No staging environment. A push to `dev` that passes CI deploys straight to production: it's deployed with `--skip-domain`, smoke-tested, then promoted. `prod` is never committed to; the pipeline fast-forwards it to the deployed SHA, so it always shows what's live. The `PROD_AUTO_DEPLOY=false` repo variable pauses automatic deploys.
- 2026-11-14 Every change reaches `dev` through a PR from a short-lived feature branch (`feat/…`, `fix/…`, `chore/…`, `claude/…` for agents), squash-merged. The `dev` ruleset requires the PR and green `ci / quality` + `ci / migrations` with 0 approvals and no bypass, so direct pushes are rejected for the owner too. The merge is the deploy decision and stays human; agents never merge.
- 2026-11-16 The public GitHub history is kept as it is. The old context7 key (rotated; revocation to be confirmed in the dashboard) stays in commits `92173c1` and `dd1485b`, and every commit carries the work email. No history rewrite and no force-push to `dev` or `prod`, so the no-force-push rule holds.
- 2026-11-16 Feature branches are named `<type>/<number>_<short_task_name>`, e.g. `feature/33_some_task_name`. `type` is `feature` (or `fix`, `chore`), the number matches the commit number, and the name uses underscores, has 1–4 words and says what the task is about. `feat` is replaced by `feature`. Agent branches keep the `claude/` prefix until decided otherwise.
- 2026-11-16 The `create-branch` skill, run by the orchestrator at task start, is the only place that creates a task branch. `commit-message` commits on the checked-out branch and never creates one.
- 2026-11-16 Each task runs on the branch `create-branch` makes, chat or backlog. When the human picks it in the `merge-branch` dialog, the branch is fast-forwarded into `dev` and deleted locally. Until then it stays checked out, so the feature can be tested first.
- 2026-11-16 Supersedes the merge rules of 2026-11-14 for local task branches: `merge-branch` fast-forwards the task branch into local `dev`, pushes `dev` to origin right away with a plain push, and then deletes the branch, only after the human picks "Merge and push". It never force-pushes. Once the planned `dev` ruleset is on, this direct push will be rejected, and that change will need a PR. PRs, squash merges and "agents never merge" still apply to `claude/` branches from cloud agents.
